Measure first, then move the furniture

The console is being reorganised around six areas and object pages, and four capabilities that the product describes but does not have are being built. This is the order that work has to happen in, what each step touches, and what will count as done. The screens themselves are in the design canvas.

01What already works

Most of what this rebuild needs is already built and tested. Listing it first is not throat-clearing — it is the difference between a redesign and a rewrite, and several of these were on the list of things to add.

CapabilityState todayVerdict
Durable command queue Written to sealed storage before dispatch; states queued → running → retry_scheduled → succeeded | needs_attention; retry ladder 2·4·8·16·32·64 s to eight attempts; a newer identical request for the same server, action and target atomically replaces the older queued one. Keep
Agent transport Outbound mutual-TLS long polls. No inbound port, no SSH, no WebSocket. Resumes after disconnection; rejects work from a stale authority epoch. Keep
Self-update, both binaries internal/warden already downloads, verifies the SHA-256 against the release, health-checks the candidate, rolls back on failure, and keeps exactly three releases on disk. Keep
Container logs internal/logstore defaults to seven-day retention with a 20 GiB cap, and says so when the cap shortens retention. Keep
Traffic Typed HTTP/TCP/UDP routes, entrypoints, Cloudflare and ArvanCloud DNS, ACME state and retry, one-action cutover. No raw label or rule is ever accepted. Keep
Source to deploy Sealed provider tokens, full-tree discovery of every Dockerfile and Compose file, and the substitution rule that replaces a repository's PostgreSQL, MongoDB, Redis, Prometheus and Jaeger with the cluster's own. Keep
Audit and action catalogue Every mutation recorded with actor and outcome; the operation vocabulary is closed and served, so an action absent from it has no route and no argv the agent will accept. Keep

02What is actually missing

Each of these was checked against the source, not against the README. Two are capability gaps, two are surfaces that exist but do not answer, and one is a subsystem to delete.

Gap 1 Nothing collects it

No host or container metrics reach Prometheus

deploy/observability/prometheus.yml has four scrape jobs: Prometheus itself, the Core API, Traefik, and Alertmanager, plus HTTP service discovery for applications. There is no job for a node and none for a container. A node-exporter runs in the agent stack and nothing scrapes it. Per-container statistics exist only as a one-shot API call behind GET /api/v1/containers/{id}/stats, stored nowhere.

Gap 2 No surface

There is no dashboard for any single thing

The Health screen draws a cluster-wide in-memory series, bounded to four hours and lost on restart. There is no page for one machine, one container, or the gateway's own traffic — which is why a chart in this console can never answer “for which node?” That question is the complaint this rebuild starts from.

Gap 3 Exists, unfindable

The core is a footnote

Control → Controller & recovery opens on a ten-row handoff timeline whose every row reads “Pending”. It never states the version, never offers an update, and shows no sign that the machine it runs on exists. The updater that could answer all three is built and unreachable from the browser.

Gap 4 Per-host only

Agent versions are managed one host at a time

POST /api/v1/servers/{id}/agent-update exists; a fleet view, an update policy, a rollout and a rollback do not. A machine two releases behind silently rejects newer commands and nothing on screen connects the two facts.

Gap 5 — Ansible is still shipped. deploy/ansible/ holds a playbook, an inventory example and three roles, and scripts/bootstrap-swarm.sh and scripts/setup-three-managers.sh both drive it. Every task it performs is also a typed agent operation. It is a second, unaudited path to the same hosts, and it goes.

03The target shape

Six areas instead of eight, and the depth moves into the object. You open a machine, a container, an application or a run, and everything about that thing — including its charts — is on its page. Observe stops being a destination for exactly that reason.

Home

What production is doing, and the one thing worth doing about it.

Apps

Applications, Deploy, Platform services, Images & registries, Stacks & services.

Machines

Machines, Swarm, Containers, Storage & networks. Setup and diagnostics move onto the host.

Traffic

Gateway, Routes, Domains & DNS, Certificates.

Activity

Runs, Logs, Audit, Action catalog.

Control

Core, Agents & updates, Settings & access.

Nothing is removed. Every screen that exists today keeps a home, and most of them stop being screens — Host setup becomes a machine's Setup tab, Connection diagnostics becomes its Agent tab, Collectors becomes Platform services, and Import from Kubernetes becomes one of the five things you can point Deploy at. Every retired hash keeps resolving.

04The phases

Ordered by dependency, not by preference. Phase 2 has nothing to read until phase 1 writes it, and the console rebuild has nothing to draw until phase 2 serves it — so the screens come last even though they are the visible part.

01

The agent becomes the measurement

no design dependency · can start now

One collector, on the host, in the process that is already there. It answers before Docker exists, needs no privileged sidecar, and its readings arrive over the connection that is already authenticated.

  • internal/hostmetrics/New. CPU per core and aggregate, load average, memory and swap, every mounted filesystem, per-interface network counters, uptime, and pressure stall where the kernel exposes it. Linux reads /proc and /sys; a darwin path exists so the thing can be developed and tested on this machine.
  • internal/containermetrics/New. Per-container CPU, memory against limit, network, block I/O, PIDs and restart count, sampled from the Docker API — labelled by container, service, stack, application and node so a query can group by any of them.
  • cmd/agent/A metrics.sample catalogue entry that returns one Prometheus-format exposition for the host and every container on it. It is a catalogued read like any other; the agent still opens no port.
  • api/http/metrics.goNew. Core pulls each connected machine's sample on a 15-second tick over the existing channel, caches the last one with its age, and serves it at GET /metrics/machines/{id}. Prometheus scrapes Core, which is the only way to collect from a fleet that has no inbound ports.
  • internal/ops/metrics_targets.goThe discovery response grows the machine targets beside the application targets it already returns, so a newly enrolled host starts being scraped without anyone editing a file.
  • deploy/observability/prometheus.ymlOne new job, swarmops-machines, using the same HTTP service discovery. The unscraped node-exporter comes out of the agent stack.
Done when

A one-node Swarm on this Mac has an enrolled agent; curl against Core's machine endpoint returns host and per-container series; Prometheus shows the target up and holds fifteen minutes of history for a container that was started and stopped during the run.

02

A closed set of readings the console can ask for

needs 01

The browser never sends PromQL. It asks for a named reading about a named object, and Core owns the query — the same rule that governs every other operation in this product.

  • internal/metrics/queries.goNew. Named, parameterised queries: host series for a machine, container series for a container, request rate and latency percentiles and error ratio for an application or route from Traefik's own metrics, and fleet aggregates.
  • api/http/Range endpoints per object — machine, container, application, gateway, cluster — each with a bounded window and a step the server picks. Every response states which source answered it and how old that reading is.
  • internal/insights/The existing in-memory series becomes the documented fallback for a cluster with no Prometheus. A screen says which one it is reading rather than averaging the two.
Done when

Every chart in the canvas has an endpoint that returns it, an absent Prometheus degrades to a stated four-hour window instead of an empty screen, and no endpoint accepts an expression.

03

Ansible comes out

independent

Every task the playbook performs already exists as a typed agent operation with an audit record. Keeping both means two ways to change a host and one of them is invisible.

  • deploy/ansible/Deleted — playbook, inventory example, and the docker_engine, swarm and swarmops_preflight roles.
  • scripts/bootstrap-swarm.sh
    scripts/setup-three-managers.sh    Rewritten against swarmopsctl: install the agent, approve it, then queue the same install, init and join operations the console queues. Same outcome, one path, every step audited.
  • README.md · deploy/README.md · CHANGELOG.mdThe Ansible sections go; the replacement path is documented where they were.
Done when

grep -ri ansible over the repository returns only changelog history, and the rewritten bootstrap script brings up a working one-node Swarm on this machine end to end.

04

The core and the fleet can be updated from the console

independent of 01–02

The mechanism exists and has no route. This phase is mostly wiring, and it is what turns Control from a recovery procedure into a place you visit.

  • api/http/core.goReleases available and installed, the running one, the process's own resident memory and CPU, state size and free disk, last backup and last verified restore; an update endpoint that drives the existing warden; an update policy of manual, windowed or never.
  • api/http/agents.goNew. Fleet version inventory, a rollout that walks machines one at a time and stops on the first failure, per-machine rollback to a kept release, and the same three-way policy.
  • internal/agentcontrol/The catalogue gains the minimum agent version each operation needs, so “this machine will reject that command” becomes a fact the console can state instead of a mystery.
Done when

An agent is updated and rolled back from the browser against the local cluster, and a deliberately failed candidate leaves the previous release serving.

05

The console is rebuilt to the six areas

needs 02 and 04 · needs the canvas signed off

The console's directory rules stay exactly as they are — this is a change of what the screens are, not of how the code is organised.

  • web/src/navigation/navigation.tsSix areas, their screens, chords and one-line purposes. Every one of today's twenty-four hashes joins LEGACY_ROUTES and resolves to its new home.
  • web/src/shell/page-router.tsxObject routes — #machine/<id>, #container/<id>, #app/<name>, #run/<id> — so the thing you are looking at is addressable and shareable.
  • web/src/components/metric-chart.tsxNew. One wrapper over the kit's Chart: a reading, its meaning, its window, and its source. Every chart in the product is this component, so “which node, over what period, measured by whom” is answered in one place.
  • web/src/screens/Machine, container and application detail pages; the gateway's traffic panels; Platform services; the consolidated Deploy flow; the rewritten Core screen. A screen is deleted only once its content has a home.
  • web/src/operator-workflows.test.mjsThe existing test that fails a routable screen with no area or no router branch is extended to object routes, so the failure mode that shipped an unreachable screen for three releases stays impossible.
Done when

Every old hash resolves, no screen shows a control without a handler, a 390-pixel viewport has no horizontal overflow, and the review harness renders all six areas against fixtures.

06

Deploy becomes one flow with five inputs

needs 05

A Git repository, an uploaded archive, a public URL, an image you already pushed, and a set of Kubernetes manifests are five ways to start the same four stages. The Kubernetes importer stops being a destination.

  • web/src/screens/apps/deploy/Source, Discovery, Plan, Release as four stages of one screen, with the substitution panel promoted: what the repository asked for, what it will get instead, and why.
  • api/http/source_api.goThe discovery response returns substitutions as first-class records — variable, previous value, new value, reason — rather than leaving the console to infer them.
Done when

A repository carrying its own PostgreSQL, Redis, Prometheus and Jaeger deploys against the local cluster, runs three services and no fifth database, and the plan shown beforehand matches what exists afterwards.

05How it gets verified

A disposable one-node Swarm on this machine, through OrbStack, plus the checks the repository already defines. Nothing below is a claim about a remote cluster.

swarmops-core ← agent, host process → OrbStack Docker → one-node Swarm → Traefik + Prometheus

Real enrolment, real certificates, real Docker, real scrapes. The agent runs as a host process on this Mac, which is the same shape it takes on a server.

06What I will not claim

Stated now, so no report later has to walk it back.

Not verified here

Multi-node Swarm behaviour, controller handoff between two real hosts, ACME issuance against a real DNS provider, and Ubuntu-specific host paths. A one-node cluster on macOS proves the mechanism, not the fleet.

Deliberately not built

Automatic controller failover. Two active cores would both believe they own the cluster; a move stays a deliberate act with a fence in the middle of it, and the console will keep saying so rather than implying a quorum it does not have.
